# Перевод интерфейса RU / EN

Исходный язык — русский. Английский словарь — `src/i18n/en/<раздел>.ts`, ключ — **точный русский текст**.

```ts
import { t } from '../../lib/i18n';          // путь — относительный, как остальные импорты в src

<h2>{t('Мои прогнозы')}</h2>
aria-label={t('Прогноз на матч')}
t('Ты {place}-й из {total}', { place, total }) // подстановки — {имя}; в переводе те же имена
plural(n, ['прогноз', 'прогноза', 'прогнозов'])  // как было; в словарь: 'прогноз|прогноза|прогнозов': 'prediction|predictions'
```

Правила:
- Русский вывод не меняется ни на символ: тесты сверяют русские строки, и ключ должен совпасть с текстом.
- Переводим всё, что видит человек: тексты, кнопки, `aria-label`, `title`, `alt`, `placeholder`, `document.title`,
  сообщения об ошибках и тостах. Комментарии и `console.*` — нет.
- Предложение с числом/именем — одной строкой с подстановками, не склейкой кусков: порядок слов в английском другой.
- «МСК» в строках времени — `t('МСК')` (в словаре 'МСК': 'MSK'). Даты — только через `ui/format` (он уже двуязычный).
- Константы модуля с `t()` можно: словарь грузится до импорта приложения. Исключение — модули, которые `main.tsx`
  грузит раньше словаря (`telegram.ts`, `lib/i18n.ts`, `lib/auth.ts`, `lib/shell.ts`, `lib/visit.ts`): в них `t()`
  только внутри функций.
- Английский — живой, как у футбольных приложений (FotMob, OneFootball): «Fixtures», «Kick-off», «Lineups», «Matchday».
  «Мадридиста» → «Madridista», «Реал» → «Real Madrid» (в коротких местах — «Real»), «Ла Лига» → «LaLiga».
- Админка (`AdminScreen`, `AdminStats`) и `dev/` — только для владельца, не переводим.
